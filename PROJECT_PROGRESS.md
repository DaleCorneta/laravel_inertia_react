- Step 10.5 — Selected Laravel Socialite `^5.31` for Google OAuth. Laravel's official Socialite documentation lists Google as a built-in provider; release notes record Laravel 13 compatibility from 5.24.3, PHP 8.1+ support, Guzzle 8 support in 5.31.0, and a Facebook OIDC nonce fix in 5.30.0. The package is MIT-licensed. No OAuth package or code was added in this evaluation.
- Recommended implementation: keep provider-specific identity mapping behind the project's small provider-adapter boundary; store only local user ID, provider, and stable provider subject in a `social_accounts` table with a unique `(provider, provider_user_id)` key. Google documents `sub` as the stable identifier and warns that email can change; never use email alone to identify or auto-link an account. Link only through an authenticated, recently reauthenticated user flow or an administrator-managed pre-link. Do not create users automatically, and do not store provider tokens for login-only use.
- Register redirect and callback routes and show the login button only when both `SOCIAL_LOGIN_ENABLED` and `GOOGLE_LOGIN_ENABLED` are true; otherwise the routes should not exist. Use Socialite's session-backed state validation, generic callback failure responses, and send the resolved active local user through the existing MFA challenge before creating an authenticated session.
